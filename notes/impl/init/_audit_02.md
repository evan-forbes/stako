# Audit — Milestone 2: Init and Layout

Baseline: f8af739. Modules audited: `src/cli.zig`, `src/init.zig`, `src/stack_config.zig`, `src/main.zig`. Tests audited: `test/init_tests.zig` (12 tests), `test/cli_tests.zig` (18 tests, M4+ but exercises init/dispatch), plus in-module unit tests in `src/cli.zig` (28) and `src/stack_config.zig` (5) and `src/init.zig` (3).

Baseline confirmed: `zig build test --summary all` → 358/358 pass.

## Execution traces

**`stako init --root /tmp/foo --yes --quiet`**: `main.zig` collects argv, builds writers, calls `cli.dispatch`. `dispatch` matches `init` via `Subcommand.fromString`, dispatches to `runInit`. `parseInitArgs` returns `InitArgs{ .root="/tmp/foo", .yes=true, .quiet=true }`. `runInit` calls `init_mod.run` with `yes = parsed.yes or true` (always true — see Blocking below). `init.run` opens the root via `openDir`, sets up `Report{ .arena, errdefer report.deinit() }`, calls `detectGit` (returns `.none` for a fresh dir), runs `gitInitHere` (manual `.git` skeleton). Then `ensureDir` × 5 for `stacks`, `stacks/default`, `.stako`, `.stako/credentials`, `.stako/runtime`. `chmodIfPosix` on credentials. `writeFileIfAbsent` for `stack.toml`, `config.toml`, `config.local.toml`, `local_token` (the token is generated via `generateLocalToken` BEFORE the file-existence check — see Important #2). `appendGitignoreLines` writes the 9 lines. `printReport` prints "created:" list — `quiet` is ignored (Blocking #2).

**`stako init` on a directory already inside a parent git repo**: `detectGit` finds no `.git` in cwd, then `realpath`s the root and walks up via `dirname`, looking for `.git` at each ancestor. On match → `.parent_repo` → `report.inside_existing_git = true`. The `if (!opts.quiet)` branch (line 109–111) is an empty block with a comment — `quiet` is wired in but does nothing. `printReport` emits the "warning: notes root is inside an existing git repository" lines unconditionally.

**`stako` (no args) and `stako frobnicate`**: `dispatch` writes usage to stderr → 2; unknown writes "unknown subcommand `frobnicate`" + usage → 2. Verified by `cli_tests.zig:410`.

**`parseStackArgs` with `--target=` empty / `--target a`**: `--target=` (empty after =) is accepted with `out.target = ""`; `--slug=` and `--prompt-file=` same. Inconsistent with `--root=` which rejects empty (lines 244-246 and elsewhere). Minor #5 below.

## Blocking

- **Blocking** — `src/cli.zig:645` — `parsed.yes or true` is a tautology that silently discards the parsed `--yes` flag. Every call from the CLI passes `yes = true` regardless of whether the user supplied it. This hides the actual default behavior, the help text claim ("Skip prompts; auto-init git when needed") is therefore inaccurate (the prompt is *never* shown because non-yes mode is unreachable from CLI). Either drop `or true` (and remove the dead non-yes branch in `init.run` lines 115–119), or replace with an explicit `= true` constant and delete the flag/help entry. Right now the parser even rejects unknown flags with `BadFlagValue` while accepting `--yes` as a no-op — caller-surprising.

- **Blocking** — `src/cli.zig:646` & `src/init.zig:109–111,738–756` — `--quiet` is parsed, threaded through, but never honored. `printReport` unconditionally writes the warning, "created:" list, and "already present:" list. The help text promises "Suppress per-line output; print a summary only." Either implement the gate in `printReport` (skip the per-path list when `opts.quiet`, print only an N-created/M-present summary), or remove the flag. Tests in `init_tests.zig` all pass `quiet = true` *for output cleanliness*, so a behavior regression here would never be caught — there's no assertion that quiet actually suppresses anything.

## Important

- **Important** — `src/init.zig:349–357` — `writeAtomic` is misnamed. It calls `createFile(.{ .truncate = true })` then `writeAll`. A crash, signal, or filesystem hiccup mid-write leaves the target half-written (e.g., a truncated `local_token` becomes a permanently broken auth secret; a truncated `config.toml` breaks daemon startup). For the M2 acceptance criterion "Atomic enough?" — it isn't. Rename to `writeFile` (and document non-atomicity) or implement the standard write-to-temp-then-rename pattern. The local_token write is the most concerning instance since the token is never regenerated on re-init.

- **Important** — `src/init.zig:168–179` — `generateLocalToken` runs unconditionally on every `stako init` invocation, even when the token file already exists. The generated bytes are dropped inside `writeFileIfAbsent`'s "already present" branch. This consumes kernel entropy on each idempotent re-init and allocates 65 bytes into the report arena that won't be freed until run() returns. Move the call inside `writeFileIfAbsent`'s "needs write" branch, or pre-check existence and only call `generateLocalToken` when needed. (Also: a deterministic test that asserts the token bytes are byte-stable across reruns would catch any regression here — currently `init: rerunning with a different seed does NOT rotate local_token` only checks the file contents are unchanged, not that the token wasn't pointlessly regenerated.)

- **Important** — `src/cli.zig:643–656` — `runInit` does not honor `opts.now_override` from the CLI's `--now=` flag in any *documented* way; it is "hidden" per the parser comment at `cli.zig:113–116`, yet it bypasses the usual flag validation (no rejection of malformed timestamps; the value flows straight into `stack.toml` as written). A user passing `--now="not a date"` will produce a `stack.toml` with `created_at = not a date` that subsequently fails to round-trip through `stack_config.parseSlice` (because the TOML date type is enforced — see `stack_config.zig:75`). No test asserts this surfaces a useful error. Recommendation: either validate the override format (`YYYY-MM-DDTHH:MM:SSZ`) at parse time, or document the flag's narrow purpose and accept the risk.

- **Important** — coverage — `src/cli.zig:631-657` `runInit` itself has no direct integration test. `init_tests.zig` exercises `init_mod.run` directly; `cli_tests.zig` exercises every subcommand except `init` through `cli.dispatch`. Nothing currently asserts that `stako init` (via the CLI surface) prints `created:`, that the exit code is 0 on success / 1 on `RootNotADirectory`, or that `printReport`'s `already_present` branch ever fires through the dispatch path. Recommend at least one `cli_tests.zig` case that runs `runCli(a, &.{"init", "--root", scratch})` and asserts `r.code == 0` + stdout contains `"created:"`.

- **Important** — `src/cli.zig:586–595` (`daemon status` printing the "stale pid file" path) is M3 code, not M2-owned. Skipping. The M2-relevant behavior of `printReport` (`src/cli.zig:738–756`) duplicates the "no changes" message ("stako init: already initialized — no changes.") while also being preceded by a `git_initialized` line that prints when zero items are *created* but git was just *initialized* (because the `git_initialized` flag is set but doesn't put an entry into `report.created`). Trace: a freshly-`git init`'d notes root where layout is then somehow already present (test fixture replay?). Result: prints "initialized git repository (.git)" then "stako init: already initialized — no changes." — contradictory. Currently unreachable in practice but worth flagging.

## Minor

- **Minor** — `src/cli.zig:213` — comment grammar: "`config`: one --set entries". Should read "one or more --set entries" or "up to 8 --set entries".

- **Minor** — `src/cli.zig:99–101` — `parseDaemonArgs` returns `error.BadFlagValue` for *both* unknown flags and stray positionals. The conflated error makes the CLI error message ("stako daemon: BadFlagValue") less directive than e.g. "unexpected positional". Stack/auth parsers have the same conflation. Minor UX nit.

- **Minor** — `src/cli.zig:84–90 / 237–246` — `--root` (space-separated) accepts an empty value silently; `--root=` rejects empty. Inconsistent. Same applies to `--port` and `--target` / `--slug` / `--prompt-file` / `--set` (the long forms with `=` don't validate emptiness, while some bare-flag forms do).

- **Minor** — `src/init.zig:411-430` — `appendGitignoreLines` reads `existing` with `f.readAll(buf)` where `buf.len == stat.size` but `existing = buf[0..n]`. If `n < stat.size` (short read), then `defer arena.free(existing)` frees the wrong slice. Currently benign — arena free is a no-op. Tightening recommended: `_ = n; existing = buf;` or just `try f.readToEndAlloc`.

- **Minor** — `src/init.zig:189–220` (`detectGit`) walks up using `dirname` and allocates a fresh copy at each step. Cheap, but a single buffer with manual length adjustment (or `std.fs.path.dirname` working in-place) avoids the alloc churn. Performance is non-critical here.

- **Minor** — `src/init.zig:222–243` (`gitInitHere`) bootstraps a minimal `.git/` without an initial commit, but writes a `config` claiming `filemode = true` — Windows users (no POSIX modes) would get a config that doesn't match reality. Trivial because the platform isn't supported by `chmodIfPosix` anyway; just worth noting.

- **Minor** — `src/cli.zig` has no `--help` / `-h` handling. `stako --help` is dispatched as an unknown subcommand. Plan doesn't require it but it's a UX gap.

- **Minor** — `src/cli.zig:474–499` (`dispatch`) returns `error.OutOfMemory` *through* the dispatch surface because each `runX` propagates `try`. `main.zig` does catch this. But the `UsageError` enum includes `OutOfMemory` — confusing factoring (parser errors and runtime allocation are different categories).

- **Minor** — `src/init.zig:68–71` — `InitError` declares `RootNotADirectory` and `PathTypeMismatch` but the `run()` function returns `!Report` with inferred error union; the typed alias is for "documentation purposes only" (per the doc comment). Either commit to using it as the return type (clearer API) or drop it.

- **Minor** — `src/init.zig:507–534` (`formatIsoUtc`) reimplements Howard Hinnant's civil-from-days inline with no reference to any of Zig's stdlib date helpers. Fine for now; if Zig 0.16+ adds a stdlib formatter, replace.

## Coverage gaps

- **Plan step 3 (prompt vs. auto-init based on `--yes`)** — no test covers non-`yes` behavior because `runInit` forces yes=true via the tautology (see Blocking #1). The design says "prompt to git init … (or proceed automatically when --yes)" — neither path is tested for an actual prompt flow (there is none).
- **`--quiet` actually suppresses per-line output** — no assertion; tests pass `quiet=true` only to keep test output clean. Combined with Blocking #2, this is invisible.
- **Init via `cli.dispatch`** — `init_tests.zig` only exercises `init_mod.run` directly. Nothing currently asserts the exit code or stdout of `runInit` end-to-end through `cli.dispatch`, including the "already initialized — no changes." branch and the `git_initialized` printer.
- **Init into a non-existent root path** — no test for `error.RootNotADirectory`. Should assert exit code 1 and a useful stderr message.
- **Init into a path the user lacks write permission on** — no test for permission-denied errdefer cleanup. Acceptable per M2 scope, but worth noting that partial-init isn't cleaned up on disk (`errdefer report.deinit()` only frees memory).
- **`.stako/runtime/` is empty after init** — acceptance bullet says "is gitignored, and is empty after init." Tested for existence + gitignored, not for emptiness.
- **`parseInitArgs` rejects `--root=`** (empty after =) — `parseInitArgs` *does* reject this (line 134); but the symmetric short form `-r ""` is silently accepted. Test asserts neither path.
- **CLI flag ordering** — `parseInitArgs` accepts flags in any order; no test for `-y --root foo` vs `--root foo -y`.
- **`--seed=` parse error path** — no test that `--seed=notanumber` returns `BadFlagValue`.
- **Idempotency with mixed pre-existing files** — only one negative case (pre-existing `config.toml`); no test for the case where `stack.toml` is pre-edited (the same "never overwrite" guarantee applies per the doc comment at `init.zig:6–11`).

## Strengths

- **Idempotency is well-tested at the integration level.** `init_tests.zig` covers fresh init, rerun-no-op, token preservation across reseed, gitignore append-without-duplicate, no-clobber of `config.toml`, parent-git proceed+warn, and full byte-stable fixture snapshot.
- **Byte-stable fixture snapshot** (`init_tests.zig:460–497`) is exactly the right tool to detect accidental schema/format drift. Fixture rename trick to dodge gitignore self-matching (`dot_gitignore`, `*.expected`) is clever and documented.
- **`PathTypeMismatch` handling** (added in `chore: review feedback` per `git log`) — the `ensureDir` / `fileExistsStrict` / `ensureWritableFileAbsent` trio correctly distinguishes "missing", "exists with the right kind", and "exists with the wrong kind". Two tests directly cover this.
- **Arena allocation for the Report** keeps the lifetime story simple — single deinit frees all path strings.
- **`stack_config.zig` round-trip test** (`writeDefaults round-trips through parser`) ensures `init`'s output is consumable by the reader; a clean invariant.
- **`generateLocalToken` deterministic-seed test** verifies hex+newline shape (65 bytes, lowercase hex), which is essential for fixture stability.
- **`detectGit` correctly distinguishes repo-here from parent-repo** using `realpath` + `dirname` walk; the resolved policy (proceed+warn for parent-repo) is enforced and tested.
- **POSIX chmod via `fchmodat`** (rather than path-based chmod) is the right call — avoids races where a path is replaced between path resolution and chmod.
- **Module-level doc comments** in `init.zig` and `cli.zig` are unusually thorough and aligned with the design docs.

# 00 — Test Strategy

Shared conventions for tests across every milestone. Each milestone's own file lists the *specific* tests for that milestone; this file covers the *how* — directory layout, fixture conventions, the credential gating mechanism, and the shared smoke-test stack.

## Layout

```
test/
  fixtures/
    items/                # per-kind meta.toml + body files (built in milestone 1)
      prompt_basic/
        meta.toml
        prompt.md
      compact_chained/
        meta.toml
      clear/
        meta.toml
      sleep_future/
        meta.toml
      sleep_elapsed/
        meta.toml
      review_with_parent/
        meta.toml
        prompt.md
      terminal_completed/
      terminal_failed/
      terminal_canceled/
      terminal_superseded/
    stacks/               # whole-stack fixtures (built in milestone 2)
      smoke/              # the canonical smoke-test stack — see "Smoke Stack" below
        stack.toml
        0001-hello/
          meta.toml
          prompt.md
        0002-followup/
          meta.toml
          prompt.md
      paused/             # stack.toml with paused = true
      chain_continuity/
      fresh_continuity/
    notes_roots/          # whole-workspace fixtures (committed-form layouts)
      empty_initialized/  # output of `stako init` on an empty dir
      with_running_item/  # meta.toml status=running plus .stako/runtime entry — used in restart-orphan tests
    harness/              # scripted fake-binary scripts (milestone 6+)
      claude_hello.jsonl  # canned stream-json a fake claude emits
      codex_hello.jsonl
      gemini_hello.jsonl
      claude_ignores_sigint.sh
  helpers/
    fake_harness.zig      # shared scripted-binary harness used by milestones 6 and 7
    daemon_spawn.zig      # spawn-daemon-on-temp-root helper used everywhere
    capability_flag.zig   # parses --with-real-credentials and per-provider gates
```

Every fixture is the *output* of running the relevant operation on a clean root, so milestones don't drift from each other's expectations. When the schema changes, the fixtures are regenerated, not edited by hand.

## Fixture Reuse

Each milestone consumes fixtures from earlier milestones rather than rebuilding them:

- Milestones 1–2 produce the `items/` and `notes_roots/empty_initialized` sets.
- Milestone 3 (daemon read endpoints) consumes both.
- Milestone 5 (mutations) regenerates `with_running_item` after each test.
- Milestone 6 adds fake-adapter scripted output and consumes `notes_roots/with_running_item`.
- Milestone 7 adds Claude/Codex scripted output.
- Milestone 9 (HTML) consumes milestone 6/7 transcript output.
- Milestone 10 reuses the smoke stack as the integration target.

The fixture format is byte-stable; tests can snapshot-diff against committed files.

## Credential-Gated Integration Tests

Tests that hit a real provider are gated behind a runtime flag, not skipped via `#ifdef`:

```
zig build test                                              # mocks only — runs in CI
zig build test -- --with-real-credentials                   # opt in to all real-provider tests
zig build test -- --with-real-credentials=anthropic         # opt in to one provider
zig build test -- --with-real-credentials=anthropic,openai  # opt in to a subset
```

Rules:

- Default (no flag) is mock-only. CI never sets the flag.
- A real-credentials test that runs without the flag prints `[skipped: real-credentials gate]` and exits 0.
- Each real-credentials test reads its credentials from the same `.stako/credentials/<provider>/auth.toml` that the daemon uses (no separate test-only credential store). Test runs from a temp-root that's populated with credentials by `helpers/capability_flag.zig` reading from `$STAKO_TEST_CREDENTIALS_DIR`.
- Real-credentials tests are tagged `@integration:provider:<name>` in test names so they can be selected/excluded by pattern.

## Smoke Stack

`test/fixtures/stacks/smoke/` is the canonical end-to-end fixture used by milestones 5–9 for sanity checks and demo runs. It contains two prompt items: a short "say hello" item and a follow-up that depends on the first. Properties that other milestones can rely on:

- `stack.toml` declares `continuity = "chain"`, `allowed_harnesses = ["claude", "codex"]` by default, and `default_workdir = "/tmp/stako-smoke-workdir"`. A separate optional Gemini fixture may add `gemini` when that adapter is enabled.
- Item 0001 routes to `provider = "anthropic"` exact; item 0002 routes to `match = "compatible"`.
- Prompts are tiny enough to run in <10 seconds against any real provider.
- The fixture is regenerated by a single helper (`tools/regen_smoke_fixture.zig`) when schemas change.

Milestone-specific tests use this fixture for:

- Milestone 3: read-path JSON correctness.
- Milestone 5: append/insert/cancel against a known starting state.
- Milestone 6: fake-adapter runtime runs, cancellation, restart, independence check across two stacks (smoke + a copy).
- Milestone 7: end-to-end Claude and Codex runs.
- Milestone 8: provider status and optional Gemini routing.
- Milestone 9: HTML rendering of a stack with a running item.
- Milestone 10: authorization checks against the mutation and dispatch surface.

## Test Categories

| Category | When it runs | Examples |
|---|---|---|
| Unit | Every build | TOML round-trip, state-machine transition table, error-responder slug → status mapping |
| Integration (mocked) | Every build, includes CI | Daemon read endpoints against fixture root; harness adapter against scripted fake binary |
| Integration (real-credentials) | Only with `--with-real-credentials[=...]` | One short prompt for Claude and Codex; OAuth/PKCE smoke where supported; Gemini advisory |
| Snapshot | Every build, committed `.expected` files | Rendered HTML pages from fixtures; audit-log NDJSON shape |
| Long-running smoke | Manual or nightly | Full smoke stack across Claude and Codex, optional Gemini, daemon restart loop |

The unit and mocked-integration tiers must pass before any milestone is considered complete. Claude and Codex real-credential smoke tests are advisory in CI but required before tagging a release. Gemini real-credential tests are advisory until Gemini is promoted from bonus scope.

## What This Doc Is Not

- Not a per-milestone test list — each milestone's file owns its own acceptance tests.
- Not a CI configuration spec — that lands once the first milestone has tests to run.
- Not a coverage target — coverage decisions happen per milestone.

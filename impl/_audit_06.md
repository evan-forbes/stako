## Execution traces

**Happy-path session lifecycle.** `Supervisor.tickStack` (runtime.zig:201) lists items via `storage.Reader.listItems`, walks them in id order, runs `routingPreflight` (runtime.zig:312) which resolves harness → checks workdir → probes the factory → optionally consults `provider_status` → returns `ProceedInfo{ .harness, .cwd }`. `dispatchItem` (runtime.zig:457) builds argv via `dispatch.build_argv`, then calls `sm.spawn`. `Manager.spawn` (session_manager.zig:182) acquires a global concurrency slot (cv-wait), dupes argv, `child.spawn()`s, opens the per-item `transcript.jsonl`, writes the `runtime/<stack>/<id>.toml` file, registers the session under the manager mutex, submits `queued→running` through the mutation queue, emits a daemon-side `session_started` event into transcript+hub, then launches three threads: `stdoutPump`, `stderrPump`, `waitForExit`. Stdout lines hand off to `adapter.parseLine` (fake_adapter.zig:54) which extracts `kind` + `data` JSON object, returns an `OwnedEvent`. `processStdoutLine` (session_manager.zig:482) rewrites `event.stack/.item/.session`, appends to transcript, publishes to the hub. On EOF/exit, `waitForExit` calls `child.wait`, joins the pumps, and `onExitMain` (session_manager.zig:547) builds the `session_ended` event via `adapter.onExit`, snapshots `[result]` fields, deletes the runtime file, submits the terminal `RuntimeTransitionInput` through the queue (which writes both `status` and `[result]` in one atomic meta.toml replacement — mutations.zig:549). `markFinished` (session_manager.zig:389) moves the session into the `finished` list under the manager mutex and signals `slot_cv`. Eventual `Manager.deinit` calls `waitAll` then frees all finished sessions; `Worker.deinit` joins the per-stack ticker thread.

**SSE subscriber lifecycle.** Browser hits `GET /stacks/{name}/events`. `handleConnection` (daemon.zig:463) parses the request head, `routeWithOwnership` (daemon.zig:623) routes to `handleStackEventsDetached` (daemon.zig:2066). The handler validates the stack name, returns 503 if `sse_hub` is null, allocates an `SseConnCtx`, dupes the stack name, calls `hub.subscribe` (sse.zig:64), reserves capacity in `sse_threads`/`sse_handles`, writes the `200 OK` SSE headers directly to `conn.stream`, spawns `sseWorkerThread`, appends the thread + handle, and sets `conn_owned.* = false` so the accept loop doesn't close the socket. The worker thread blocks on `stream.read` (one-way SSE). When `hub.publish` fans events out (sse.zig:96), it snapshots subscriber pointers under the hub mutex, bumps each ref_count, drops the mutex, then calls each `sink.write_fn` (daemon.zig:2043 → `stream.writeAll`). `releasePublishedSubscription` re-acquires the mutex, decrements ref_count, removes a failed sink into `retired`. On client disconnect the worker's read returns 0, unsubscribes (which waits for ref_count to drain, then destroys the subscription), `stream.close`s, frees ctx. Daemon shutdown short-circuits this: `Daemon.deinit` (daemon.zig:148) tears down in order: supervisor → queue → SSE handles force-shutdown → SSE threads joined → hub deinit (only when daemon-owned) → audit → server → pidfile. The supervisor goes first because session wait-threads still submit terminal transitions through the queue, and the SSE force-shutdown only happens after the supervisor is fully drained — so no publish is in flight while sockets are being torn down.

**Stack pause → resume.** `tickStack` reads stack config; if `cfg.paused` is true it returns immediately (runtime.zig:208). No items are dispatched and `running_count` doesn't move. Resume is purely a stack.toml flip via the mutation queue's `config_patch` request; the next `Worker.workerMain` tick (every 100 ms by default, see runtime.zig:565) re-reads the config and proceeds. The audited paused test (runtime_tests.zig:309) verifies the item stays `queued` after a tick on a paused stack. There is no in-process "paused timer wheel" — sleep items with future `until` simply stay queued, re-evaluated each tick (runtime.zig:288).

**Failure injection — stubborn subprocess.** The cancel-escalation test (runtime_tests.zig:442) spawns `claude_ignores_sigint.sh` via the fake-stubborn dispatch, then calls `sm.cancelAndEscalate("demo","0001", 250ms, 500ms)`. The method calls `cancel` (sets `outcome.canceled = true`, sends SIGINT), polls `isAlive`, after 250 ms sends SIGTERM, after another 500 ms sends SIGKILL. The pumps drain when stdout/stderr close, `waitForExit` reaps with `term = .Signal`, `onExitMain` computes `canceled = true`, picks `tag = .canceled`, builds `RuntimeTransitionInput{ to=.canceled, canceled_by="system", result_*=adapter snapshot }`, submits to the queue. The meta.toml lands at `status = "canceled"` with a `[result]` block populated from the captured session_ended payload.

## Concurrency model

Threads at steady state for an active daemon:

- **Main thread** — `serveUntilShutdown` accept loop; touches `Daemon.shutdown_requested` (atomic), spawns request-handler frames synchronously per accept.
- **Mutation-queue worker** (one) — `mutation_queue.workerMain`; protected by `Queue.mutex`/`cv`; owns all writes to meta.toml/stack.toml/audit.log; the only writer to git for tracked artifacts.
- **Per-stack `Worker`** (N=#stacks) — `runtime.workerMain`; uses `Worker.mutex/cv` (wake_pending, shutdown). Calls into the supervisor, which calls into the session manager (its own mutex) and reads via `storage.Reader` (per-call read state, no shared state).
- **Per-session pumps** (2 × #running sessions) — `stdoutPump`, `stderrPump`; touch the session's transcript writer (transcript.mutex), session_id (session.session_id_mutex), hub.publish (hub.mutex/cv). Append-only to transcript with `file.sync()` per event.
- **Per-session wait thread** (1 × #running sessions) — `waitForExit`; calls onExitMain → adapter.onExit → transcript.append → hub.publish → mutation_queue.submitAndWait → markFinished (manager.mutex, slot_cv signal).
- **SSE worker threads** (M=#subscribers) — `sseWorkerThread`; touch hub via subscribe/unsubscribe (hub.mutex/cv), `sse_threads_mu` only at spawn/join; otherwise just block on `stream.read`. Sink callbacks run on the publishing thread, not on the SSE worker.
- **Cancel-escalate caller** (transient) — `cancelAndEscalate` runs on whatever thread invokes it (HTTP handler today); reads `child.id`, sends signals.

Shared structures and their locks:

| Structure | Lock | Touched by |
|---|---|---|
| `Manager.sessions`, `.finished`, `.running_count`, `slot_cv` | `Manager.mutex` | spawn / waitAll / markFinished / cancel / requestShutdown |
| `Session.session_id` | `Session.session_id_mutex` | pumps + onExit + (via mutex) writers reading current id |
| `transcript.Writer.file` | `Writer.mutex` | stdoutPump, stderrPump, onExitMain, session_started emit |
| `Hub.subs`, `.retired`, `.next_id`, ref_count, `cond` | `Hub.mutex`/`cond` | subscribe / unsubscribe / publish / releasePublished |
| `Daemon.sse_threads`, `.sse_handles` | `sse_threads_mu` | handleStackEventsDetached / requestShutdown / deinit |
| `Daemon.shutdown_requested` | atomic only | every thread |
| `Manager.shutdown_requested` | atomic only | every thread |
| `RunOutcome.canceled` / `.finished` | atomic only | pumps + onExit + cancel |
| `Worker.shutdown`, `.wake_pending` | `Worker.mutex`/`cv` | wake / requestShutdown / workerMain |
| `Supervisor.workers` | `Supervisor.mutex` | ensureWorker / wakeAllWorkers / requestShutdown / deinit |
| `Supervisor.status_cache` | `status_cache_mu` | `providerStatus` |
| `Queue.items`, `.closed`, `.cv` | `Queue.mutex`/`cv` | submitAndWait / dequeueOne / close / deinit |

Lock ordering observed (acquired top→bottom, never the reverse):

1. `Supervisor.mutex` — outermost; never nests other supervisor-side locks.
2. `Manager.mutex` — held alone while consulting `running_count`/sessions/finished. Drops before signalling slot_cv listeners.
3. `Hub.mutex` — held alone during snapshot; explicitly dropped before invoking sink callbacks (sse.zig:130). This avoids the publish-thread → sink → re-entry deadlock.
4. `transcript.mutex` — held only across `writeEvent` + `file.writeAll` + `file.sync`. Never nests any other lock.
5. `Queue.mutex` — submit holds this only to enqueue; the worker holds it only to dequeue. `submitAndWait` waits on a per-request `done_mutex/cv`, not on the queue mutex.

No lock-order cycle is reachable: `Manager.mutex` never reaches into the hub or queue while held; the hub is released before sinks; the queue's mutex is released before per-request waits.

## SSE-flake investigation

Repro attempts: 50 stress runs of the full suite (`zig build test`) failed to reproduce the signal-6 abort. Cannot prove the bug absent.

Most-likely suspect, by inspection: **the `handleStackEventsDetached` 200-OK-write path is non-flushed under the `std.http.Server` net_writer, but the SSE handler bypasses it.** Specifically, `handleConnection` (daemon.zig:463) allocates a `net_writer` over `conn.stream` with a 16 KiB write buffer. `handleStackEventsDetached` writes the SSE 200-OK headers directly via `conn.stream.writeAll(sse_head)` at daemon.zig:2123, completely bypassing `net_writer`'s buffer. Any bytes the std http server queued into `net_writer` during `receiveHead` (none in the happy path, but the implementation is opaque) would be silently dropped when `handleConnection`'s stack frame unwinds. More importantly, the net_writer holds a write_buf pointer that becomes invalid the moment `handleConnection` returns, while the std http machinery still has live references via `http_server.head_buffer`. If the std HTTP receiver opened any background tracking on `conn.stream.handle`, the detached SSE worker would race with it. We don't see this in 50 runs but the architecture is fragile.

A second, more concrete suspect is the **`dispatchItem` clobber-by-spawn-failure** in runtime.zig:483-505: when `sm.spawn` fails, the closure submits a `to=.failed` transition, then `return e`. The caller (`workerMain`, runtime.zig:614) catches the error with `.tickStack(...) catch {}`. **But the `dispatchItem` errdefer runs `adapter.deinit(self.allocator)` while the spawn-side `cleanupRegisteredSpawnFailure` has already set `adapter_owned = false` and called `sess.deinit()`** — net effect is a single deinit, which is correct. However, if `sm.spawn` enters the `sessions.append` failure path (session_manager.zig:278-286), it calls `sess.deinit()` while the `errdefer t.deinit()` at line 240 is also still live in the spawn frame. Both will fire and **double-close the transcript File and double-free `transcript.path`** if `sessions.append` returns OOM. The same path then runs the `errdefer self.allocator.destroy(sess)` at line 247, double-destroying. This is unlikely to be the signal-6 culprit (OOM at append is rare) but is a latent crash if memory ever does run out — see "Important" below.

A third suspect for the original abort: when the *first* test thread `th` runs `serveOne` and the handler detaches via `conn_owned = false`, the handler returns. `handleConnection`'s `var net_reader = conn.stream.reader(&read_buf)` and the underlying `http_server` go out of scope, freeing their internal allocations. Meanwhile the SSE worker holds only `conn.stream` (a value-copy of the underlying file handle struct). On Linux this is just an fd, so it's safe. But on the test client side, the test mutates `sc.n = 1` (runtime_tests.zig:969) **after** `th.join()` — that's correctly sequenced. If a future refactor lifts the `th.join()` above the SSE response read, this becomes a data race on `sc.n`. Not the current bug.

## Supervisor wiring verification

Confirmed. `Daemon.startWorker` (daemon.zig:254-300) allocates the heap `sse.Hub` (daemon.zig:259-262), allocates the heap `runtime.Supervisor` (daemon.zig:271-282), calls `sup_p.reconcileOrphans()` (daemon.zig:291), then `sup_p.startAllWorkers()` (daemon.zig:292). `startAllWorkers` (runtime.zig:175-184) lists every stack via `storage.Reader.listStacks` and calls `Worker.start` on each — which kicks off `workerMain` with `wake_pending = true`, so it ticks immediately. `Daemon.deinit` (daemon.zig:148-208) destroys the supervisor first (line 158-162), which joins both the worker threads and the session-manager wait_threads via `Supervisor.deinit → workers loop → Worker.deinit (join) → sm.deinit (waitAll)`. The end-to-end `runtime: daemon-owned supervisor drives a seeded item to completed without tickStack` test (runtime_tests.zig:1010-1115) verifies the supervisor actually drives a queued item to `completed` without any in-test tickStack call, confirming the wiring is still live. The `chore: review feedback` commit reordered `sm.deinit()` to run *after* the workers (runtime.zig:118-121) so worker ticks no longer race with sm shutdown — still correct.

## Important

- **`session_manager.spawn` post-register failure path double-deinit (session_manager.zig:278-286).** When `self.sessions.append` returns OOM, the catch block manually invokes `sess.deinit()` and `destroy(sess)`. Two outstanding errdefers (`t.deinit()` at line 240, `destroy(sess)` at line 247) then fire on the way out, double-closing the transcript File, double-freeing `transcript.path`, and double-destroying the Session. The window is small (only OOM on `ArrayList.append`) but the consequences are use-after-free in a process that's already heap-pressured. Fix: set a flag like `sess_owned_by_us = false` before manual cleanup, and have the errdefers honor it; or rearrange so the registration is the first thing after the `Session` is fully constructed and successful, then return without the manual cleanup branch.
- **`hub.publish` releases the mutex before sink callbacks but doesn't unsubscribe-by-ID-not-pointer (sse.zig:132-135).** A sink that closes its own context inside `write_fn` is impossible today (sinks are stateless re: subscription), but the contract is fragile: the only thing keeping the subscription alive across the callback is `ref_count`. If anyone ever adds a code path that calls `unsubscribe` from inside `write_fn`, the wait-on-condvar inside `unsubscribe` will block the publishing thread forever (the publish hasn't dropped its ref yet). Worth a doc-comment or an assertion. Low risk in current code.
- **`fake_adapter.parseStderrLine` `_ = impl;` discards the per-session state (fake_adapter.zig:92-93).** A stderr line should at least carry `event.session = st.session_id`, but the current implementation hardcodes empty. session_manager rewrites `event.session` from the session-id mutex afterward (session_manager.zig:540), so the field still ends up correct. But fake_adapter's contract drift may surprise a future test author who expects parseStderrLine to attach session info itself.
- **Worker poll interval is hard-coded 100 ms (runtime.zig:565)** and the mutation queue does **not** wake workers — see comments at runtime.zig:561-565. This means every mutation that enqueues an item makes the user wait up to 100 ms for that stack's worker to notice. The supervisor does provide `wakeAllWorkers`, but neither the queue nor the daemon mutation endpoints call it after a successful append/insert/retry. The fix is small (a hook from the queue post-commit into `supervisor.wakeAllWorkers`); leaving it on the table just means user-perceptible latency.

## Minor

- `events.parseEvent` is a hand-rolled byte scanner (events.zig:148-181). It tolerates leading whitespace but does not validate that all required fields are present beyond `kind`. A line like `{"kind":"message"}` parses to `{ .v = 0, .stack = "", .item = "", .session = "", .kind = .message, .data_json = "{}" }` — silently filling defaults. The transcript-write path always emits a fully-populated envelope so this isn't observable in production, but a hostile JSON source would slip through. Document the borrowed-from-`line` lifetime of the returned slices in the docstring.
- `events.parseEvent`'s `findObjectField` (events.zig:209-243) treats `}` outside a string as object-end. It does not validate JSON syntax. A line whose `data` field contains an unbalanced quote in a non-string-state path could underflow `depth` (line 238 `depth -= 1`) when depth is 0 — `usize` underflow → panic in safety builds. Today no event source produces this, but a corrupt transcript loaded by HTML rendering or restart could trip it. Same applies to `fake_adapter.findObjectValue`.
- `transcript.Writer.append` does `self.file.sync() catch {}` per event (transcript.zig:56). Per-event fsync on a 100-event-turn run is ~100 fsyncs. On a slow disk this serializes the pump. The per-event durability is over-strong; an interim batched-fsync (e.g. every 10 events or every 100 ms) would be a simple win, but only after measuring.
- `runtime_file.read` (runtime_file.zig:131-153) is a hand-rolled mini-TOML parser. It splits on `\n` and strips one layer of `"` from values — it does not handle TOML escape sequences inside the string. Round-trip works because the writer (runtime_file.zig:220-229) does the inverse escape. But a transcript_path with literal `\n` would round-trip to the literal newline on read, breaking the parser's line split. Real filesystem paths don't contain newlines, so this is theoretical.
- `runtime.handleSleepItem` (runtime.zig:258-291) treats an unparseable `until` as "now" (line 262). Surfacing as `failed` with `sleep_until_invalid` would be more honest. Currently a malformed sleep item silently completes.
- `runtime.fakeDispatch`'s `fakeBuildArgv` (runtime.zig:633-641) hardcodes `/usr/bin/true`. The m8 test at runtime_tests.zig:1191 ("preflight disabled allows the fake-harness path") relies on this. Won't work on hosts where `/usr/bin/true` lives elsewhere (some BSD/macOS variants put it in `/bin/true`). Cross-platform v1 isn't a goal but worth noting.
- `session_manager.applyTransition` (session_manager.zig:434-441) submits a request synchronously and discards `req.err`. If the queue replies with `.internal` (e.g. due to closure during shutdown), the session silently fails to record. Logging the error to the audit writer would help post-mortem investigation.
- `runtime.dispatchItem` does `_ = self.sm.spawn(...)` (runtime.zig:483). The session pointer is intentionally ignored, but a comment would help future readers — it looks at first like a discarded return value worth using for cancellation hooks.
- `Session.deinit` joins `wait_thread` THEN `stdout/stderr` (session_manager.zig:67-72). `wait_thread` already calls `joinPumpThreads` (session_manager.zig:467); the redundant join in deinit is harmless (joined threads return immediately) but is dead code worth removing for traceability.
- The `Supervisor.tickStack` walk dispatches up to `per_stack_limit - running_in_stack` items in one tick (runtime.zig:218-256). The variable `running_in_stack` is incremented after each successful dispatch (line 252) but is NOT updated when a session that was running on entry has already finished mid-tick. This is fine because each spawn submits `queued→running` synchronously, but the comment loop is subtle enough to warrant a docstring.

## Coverage gaps

- **No SSE concurrent-subscriber test.** All SSE tests run with at most one subscriber. The Hub design supports many, the publish path snapshot is per-publish, but nothing exercises N>1.
- **No "subscriber disconnects during publish" test.** The retired-list path (sse.zig:138-147) is exercised by the fail-sink unit test (sse.zig:241), but not against a real HTTP client mid-stream.
- **No mid-session daemon-shutdown test.** Cancel-escalate exercises in-process cancellation, but not "subprocess is mid-stream, `Daemon.deinit` is called from outside (CLI signal handler)". The shape of the test would mirror runtime_tests.zig:1010 with an injected `requestShutdown` mid-run, asserting the item lands as `canceled`/`failed` and no runtime file lingers.
- **No `runtime_file.toml` round-trip with embedded special characters.** The parser tolerates the simplest TOML strings; quoting an `=` inside `transcript_path` would silently truncate (the parser uses `indexOfScalar('=', line)`).
- **No `[result]` test where `session_ended.data_json` is empty** (e.g. fake adapter with `ran_to_completion=false`). The terminal-status branching in onExitMain still produces a result block (because exit_code is always non-null), but the fields end up minimal. Should be a unit test.
- **`fake_adapter.parseLine` malformed-JSON tests exercise the error event, but never the "two lines, one malformed, recovery"** flow that exercises a transcript with both `error` and subsequent `message` events.
- **`runtime.routingPreflight` is not unit-tested directly.** All preflight checks ride on `tickStack`. A targeted test for `harness_unsupported_capability` (a compact item against a harness whose `supports(.compact)` returns false) would be cheap and is the only canonical-reason-slug not covered today.
- **`Supervisor.wakeAllWorkers` has no test.** Not user-facing, but the daemon mutation surface should eventually call it (see "Important" #4).
- **`Manager.cancelAndEscalate` SIGKILL escalation** is tested for SIGINT→SIGTERM but not the second escalation. A subprocess that ignores both SIGINT and SIGTERM would exercise it; today's `claude_ignores_sigint.sh` only ignores SIGINT.
- **Worker thread cancellation under heavy churn.** No test creates a stack, kicks the worker, then immediately tears down the supervisor; the daemon-driven test (runtime_tests.zig:1010) waits for completion first.

## Strengths

- **Tear-down order is documented and correct.** The block comment at daemon.zig:149-157 spells out the four-step sequence; reading it once tells you exactly why each level lives where it does. Few audited codebases earn this.
- **Adapter contract is clean.** `OwnedEvent { ev, storage }` makes the borrow lifetime explicit at the type level — adapters dupe into the `storage` slice, the session manager frees both atomically via `adapter_mod.freeOwned`.
- **`[result]` snooping is defensive.** session_manager.zig:567-616 dupes adapter-captured strings before freeing the OwnedEvent, then re-locks the session_id_mutex for the fallback. Each step is annotated with *why* the slice would otherwise dangle.
- **Hub ref_count + retired-list pattern lets unsubscribe safely race with publish.** The condvar wait inside `unsubscribe` (sse.zig:90) is exactly the right primitive — no spin loop, no busy-wait, and the destroy-after-drain order is correct.
- **Runtime supervisor → worker → session-manager separation matches design_runtime_loop.md cleanly.** Each layer has one job. The trace through `tickStack → routingPreflight → dispatchItem → sm.spawn → pumps → onExitMain → markFinished` is linear; no module reaches up.
- **Workdir allowlist canonicalizes with realpath fallback (runtime.zig:529-540) and requires a path-boundary match (runtime.zig:533-540).** `/tmp/allowed-other` does not match `/tmp/allowed`. Few v1 implementations get this subtle prefix bug right on the first pass.
- **Session manager respects the single-writer invariant.** Every status transition — including from the runtime — goes through `mutation_queue.submitAndWait`, never directly to meta.toml. The internal `runtime_transition` kind is gated server-side (the HTTP router has no case for it), preserving the design's "the runtime is not a second writer" rule.
- **Restart-orphan recovery is idempotent and tested.** `reconcileOrphans` (runtime.zig:134-153) tolerates missing files, ignores transition failures, and always deletes the runtime file. Both the synthetic-orphan test (runtime_tests.zig:507) and the fixture-orphan test (runtime_tests.zig:692) pass.
- **Event schema versioning.** Every line carries `"v":1`. Adding new kinds is additive (the enum's `fromString` returns null for unknown), and adapters can be added without recompiling the daemon's transcript reader.

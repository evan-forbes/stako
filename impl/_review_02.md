## Non-blocking

- `src/cli.zig:106` — `.yes = parsed.yes or true` makes the runtime `yes` flag unconditionally `true`. The comment says "non-interactive in this milestone", but the consequence is that `init.zig:111-118`'s `else` branch (the "no --yes, skip git init" path) is dead code. If interactivity is genuinely deferred to a later milestone, drop the field plumbing or `std.debug.assert(opts.yes)` so the contract is explicit; otherwise wire actual prompting now. Plan step 3 ("prompt or auto-init based on `--yes`") is only half-implemented.
- `src/init.zig:28, src/cli.zig:107` — `opts.quiet` is plumbed all the way to `printReport`, but `printReport` never consults it. `--quiet` is documented as "Suppress per-line output; print a summary only" yet observed behavior shows the full per-line list. Either delete the flag or honor it.
- `src/init.zig:107-110` — the comment claims "Warning is written to stderr by the CLI layer", but `printReport` writes the warning to the same writer it uses for everything else, i.e. stdout (confirmed via `1>/tmp/out 2>/tmp/err` on a parent-git invocation: stdout receives the warning, stderr is empty). Either route the warning through `stderr` in the CLI, or update the comment.
- `src/init.zig:373-432` — `appendGitignoreLines` reports a modify-only update as `created`. The "we don't have a separate bucket for 'modified'; lump it into `created`" comment acknowledges this, but it means the summary's "created:" list contains `.gitignore` even on runs where the file only had a couple of lines appended. A `modified` bucket would clean the output and make the change-count signal more honest.
- `src/cli.zig:144-162` — when a re-init has zero changes, `printReport` prints "already initialized — no changes" and silently returns, dropping the `already_present` table. Plan step 8 says "Print a summary table of what was created vs. present." Honoring that on the no-change branch would also surface the gating issue that distinguishes "fully present" from "partial init".
- `test/init_tests.zig:338-365` — the parent-git test asserts `report.inside_existing_git == true` but does NOT capture the writer output to confirm the warning text reaches the user. Given the stdout-vs-stderr concern above, adding `dispatch(...)` with an `ArrayList` writer and asserting the warning string would lock the behavior in.
- `src/cli.zig:69-90` — `dispatch` and `runInit` have no tests, even though the file has unit coverage for `parseInitArgs`. A single dispatch test with an `ArrayList(u8)` writer (covering `init` success, unknown subcommand, no-subcommand, and bad-flag) would close the loop.
- `src/init.zig:230-242` — hand-rolled `git init` omits the `[user]`, `[init.defaultBranch]`, and `core.symlinks/ignorecase/precomposeunicode` lines a real `git init` writes. `git status` works against the layout (verified), but `git commit` would refuse without a user identity, and `core.repositoryformatversion = 0` alone is the bare minimum. Acceptable for milestone 2 (no commits are made), but the next milestone that wants to commit will need to extend this OR fall back to `git` subprocess. Add a TODO at `gitInitHere`.
- `src/init.zig:265-268` — `chmodIfPosix` is called explicitly for `.organo/credentials` but NOT for `.organo` itself or `.organo/runtime`. The design says `credentials/` is 0700; nothing forbids 0755 on `.organo` and `runtime`, so this is fine, but the layout would be more defensible with `.organo` at 0700 too (it contains `local_token` and credentials). Document the choice or tighten.
- `src/init.zig:131-145` — when `opts.now_override == null`, the timestamp comes from `std.time.timestamp()` and is formatted by hand in `formatIsoUtc`. Tests only exercise the override path; the production timestamp path has zero test coverage. A test that asserts the resulting `stack.toml` parses cleanly when `now_override` is `null` (just check `cfg.created_at != null` and that it round-trips) would close this gap.
- `src/init.zig:450-467` — `generateLocalToken` does 32 bytes of hex (64 chars) which gives 256 bits of entropy. Design doesn't pin a length; this is reasonable. No issue, just flagging that it's an undocumented constant.
- `src/stack_config.zig:107-118` — `writeDefaults` emits `description = "default stack"`, which technically isn't a *default* — the field has no default (it's optional/free-text). Design says `stacks/default/stack.toml` is created "with defaults". Either rename `writeDefaults` to `writeInitial`, or drop `description` from the file so it's actually defaults-only.
- `test/fixtures/stacks/` — 00_test_strategy.md says milestone 2 produces both `items/` and `stacks/` fixture trees, including the smoke stack at `test/fixtures/stacks/smoke/`. The directory doesn't exist. Plan 02 doesn't itself ask for the smoke stack, so this is consistent with the milestone-2 plan but inconsistent with the strategy doc. Tighten one or the other; likely the strategy doc since smoke is consumed by milestone 5+.
- `src/cli.zig:36-65` — `parseInitArgs` accepts hidden flags `--now=`/`--seed=` but the rejection-of-unknown-flags test at line 189 only verifies `--nope` is rejected. Add a positive case for `--now=2026-05-10T14:00:00Z` parsing and a malformed-seed (e.g. `--seed=notanumber`) rejection test to lock the fixture-regen interface in.
- `src/cli.zig:135-141` — `printInitUsage` doesn't mention `--now=` and `--seed=`. That's correct (the flags are intentionally hidden) but the test "parseInitArgs: unknown flag rejected" doesn't double-check they're absent from the help text. Low-impact.
- `src/init.zig:190-219` — `detectGit` walks ancestors of the *realpath* of `root_path`. If the real-path resolution fails (e.g. permission denied), it silently returns `.none`, which then causes a fresh `.git` to be initialized in the notes root even though a parent repo exists. Unlikely in practice but an edge case worth a comment.
